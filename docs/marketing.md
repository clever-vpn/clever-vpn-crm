# 营销手册（按场景查配置）

> Last updated: 2026-10-26 — 只描述**现在能配出来的**；规划中的放在 §10。
> 设计取舍与"为什么不做什么"见 [`promotion.md`](promotion.md)；接口字段见
> `clever-vpn-docs/docs/contracts/app-crm.md` §2.9。

这本手册面向**租户运营**：先按你要达成的目标找到场景，照着"设置"那几行填，就能配出来。
每个场景都写明「用什么 / 怎么设 / 用户看到什么 / 注意什么」。

## 0. 先把概念弄清楚

### 0.1 「活动」= 你在后台建的那一条规则

后台「促销」页有三个标签：**优惠券 / 礼包 / 邀请返利**。你在其中**新建一条记录**，这条记录就叫一个「活动」。它是**配置的单位，也是所有统计的单位**。

一条活动就是一整套规则，结构只有两层：

```
活动（一条规则，六个维度见 §0.2）
└─ 码 0..N 个（只有优惠券和礼包用得上）

活动 1 ──< 码 0..N ──< 核销记录
```

**注意"活动"不等于"一次推广动作"**：它是一条**可复用的规则**。同一个活动可以发 500
个码，也可以不发码直接对所有人生效。核销量、名额、报表都以"活动"为单位统计 —— 所以
"抖音 8 折"和"公众号减 5 元"要建**两个**活动，否则你分不清哪个渠道有效。

> 下文所有"活动"都是这个意思；提到某个渠道/人群时说的是"活动的类型 / 设置"，不是另一
> 个概念。

### 0.2 三种类型，六个信息维度

**类型**决定它改什么：

| 类型 | 干什么 | 不干什么 | 能在定价页展示吗 |
|---|---|---|---|
| **优惠券** | 让这一单**少收钱** | 不改时长、不改流量 | 能（选自动生效时） |
| **礼包** | **送权益**（天数 / 流量） | 一分钱都不碰 | 不能（没有价格位，赠品位规划中） |
| **邀请** | 记住"谁拉来的"，给双方奖励 | 不能当普通优惠码用 | 不能 |

### 0.2.1 免费试用不是"活动"，是一份套餐

| | 礼包 | 免费试用 |
|---|---|---|
| 是什么 | **营销动作**：给已有订阅加时长 / 加流量 | **一份套餐**：7 天 + 10GB + 1 台设备 |
| 配置在哪 | 促销 → 新建礼包 | 套餐 → 新建套餐 → 勾「设为免费试用套餐」 |
| 能不能重复 | 按人群 / 冷却 / 次数 | **全库只有一个**；每人只开一次 |
| 怎么给用户 | 后台发放 / 兑换码 / 注册自动 | **注册成功即自动开通**，不需要任何码 |
| App 怎么知道 | 不告诉 App | 注册页调 `GET /trial` 显示"注册即送 7 天" |

一句话：**能不能免费试用由套餐决定，送不送额外的天数流量由礼包决定。**
两者互不替代 —— 礼包回答不了"这 7 天给多少流量、几条线路"。

配置三步：

1. 套餐 → 新建：类型选「周期」、填天数（= 试用时长）与每月额度，勾「设为免费试用套餐」（价格和可见性会被自动锁定为 0 元 / 隐藏）；
2. 发布；
3. 让客人在注册页看到提示 —— 官网 / App 拉 `GET /trial` 即可（返回 `{available, days, quota_gb, text}`）。

⚠️ 试用套餐的设备数要与正式套餐一致，否则转正时平台会换激活码，用户要重新登录。

**六个维度**描述这一条活动的全部信息 —— 后台表单就是按这个顺序排的，你填的每一项都属于其中一维：

| 维度 | 这一维回答什么 | 具体项 |
|---|---|---|
| ① **身份** | 它是什么 | 类型、名称（只有后台可见）、状态（草稿 / 进行中 / 已结束） |
| ② **给什么** | 给多少 | 券：减固定金额 / 打折 + 最低消费<br>礼包：送天数 / 送流量 GB<br>邀请：邀请人奖励（天数 / GB） |
| ③ **给谁** | 谁有资格 | 人群（所有人 / 新客 / 老客 / 快到期 / 已过期 / 指定客户）、`N 天内到期`、`注册 N 天内` |
| ④ **用在哪些套餐** | 这一单能不能用 | 套餐类型（周期 / 流量 / 加购）、指定套餐 ID |
| ⑤ **什么时候 · 多少** | 有效期与额度 | 开始 / 结束时间、总名额、冷却；每人次数固定 1，不可配 |
| ⑥ **怎么送达 · 怎么展示** | 用户从哪遇到它 | 生效方式（自动 / 凭码）、发码方式（共享码 / 一人一码）、定价页展示 + 角标文案 |

同一套维度，三种类型的适用范围不一样：

| 维度 | 优惠券 | 礼包 | 邀请 |
|---|---|---|---|
| ① 身份 | ✅ | ✅ | ✅ |
| ② 给什么 | 力度 + 最低消费 | 奖励项 | 邀请人奖励 |
| ③ 给谁 | ✅ | ✅ | ✅（决定被邀请人拿到的首单优惠） |
| ④ 用在哪些套餐 | ✅ | ⚠️ 按**客户当前订阅**的套餐判定，不是他要买的套餐 | — |
| ⑤ 什么时候 · 多少 | ✅（总名额只对自动券有效，凭码的名额在码上） | ✅（名额在码上） | —（靠关系，不设名额） |
| ⑥ 怎么送达 | ✅ | ✅ | —（注册时填邀请码，不需要投放码） |

三点容易记错的：

- **②③④⑤ 是"资格"（能不能用），⑥ 是"触达"（怎么让他知道）**。一个活动可能资格完全正确、但没人知道 —— 那就是配置问题，不是系统问题。
- **"每人次数"不是可配项**：所有活动都固定每人 1 次（见 §0.5）。
- **"指定客户"是 ③ 的一种取值**，名单本身只是它的实现载体，不是第七个维度。

### 0.3 每个活动只有三种送达方式

不管优惠券还是礼包，**用户拿到它的方式只有三种**：

| 送达方式 | 用户要做什么 | 优惠券 | 礼包 |
|---|---|---|---|
| **无码** | 什么都不用做 | 自动生效：打开定价页就看得见，结账自动抵扣 | 系统直接发（首单成功后 / 到期前自动扫），或你在后台手动发、按名单发 |
| **共享码** | 输一个大家共用的码 | 1 个码，`多少人可用 = N`：前 N 人各用 1 次 | 1 个兑换码，前 N 人各领 1 次 |
| **一人一码** | 输自己那一个码 | N 个码，每个只能用 1 次 | N 个兑换码，每个只能领 1 次 |

**邀请是例外，它只有「无码」一种**：靠注册时填的邀请码建立"谁拉来的"这层关系，没有共享码/一人一码之分。而且那串字符**不是促销码** —— 它只用于归因，不能拿去结账页减钱。

码的数量由你填，**码本身由系统生成**（8 位，去掉了 `0/O/1/I`），你不用自己编。

> 共享码和一人一码**不是两种功能，是同一张表的两种写法**：共享码 = 1 个码 + 名额 100；一人一码 = 100 个码 + 每码 1 次。

### 0.3.1 礼包的两种到账方式：**自动到账** vs **待领取**

上面那张表说的是"用户怎么拿到这张券"；对**礼包**还有第二个问题：**拿到了之后，
权益是马上就加上去，还是他自己点一下才加上去**。这一栏在后台叫「送达方式」。

| 送达方式 | 触发之后发生什么 | 用户感知 | 用在哪 |
|---|---|---|---|
| **自动到账**（`auto`） | 权益立刻写进订阅（`expires_at` / `period_extra_gb`），并留一张 0 元订单 | ❌ 几乎为零：没人告诉他，他只会到期满那天才发现 | 补偿、悄悄回馈（这类事本来就不需要用户知道） |
| **待领取**（`claim`） | 只生成一张**待领取的券**（`promotion_claims`）。订阅一点没动、没有订单、名额也没被占 | ✅ 高：App / 官网的「我的礼包」里有一张卡，写着送什么、还剩几天作废 | **所有想被看见的营销** |

为什么要专门做「待领取」：**悄悄改账不是营销**。把 3 个月改成 3 个月零 10 天，
用户不会记住"11 月 6 日"变成"11 月 16 日"，他只会在某天发现自己"居然还能用"——
那时他既不知道是你给的，也不知道给了多少。必须有个**领取**动作，福利才是
"看得见、记得住、会跟人说"的东西。

「待领取」的几条规则（都是自动的，不用你操心）：

- **有效期**：后台填 `N 天内领取`（1–90 天，默认 7）。过期作废，卡片变灰显示「已过期」。
- **作废不等死人**：活动再次触发（下次到期扫描 / 你再手动发一次）会**重新发一张**，
  不会永远卡着。
- **不点不占名额**：核销（`redemptions`）、0 元订单、营销统计都只在**领取那一刻**才产生。
  所以"发了 100 张只领了 30 张"在报表里就是 30 —— 那是真实触达。
- **收不下就不发**：如果他的套餐根本用不上这份礼包（不限量却只送流量、永久却只送天数），
  系统连券都不生成，免得他点开一张永远领不掉的卡。
- **领取时不再重判人群**：券是按他**当时**的身份点名的。今天他是新客、明天他付了钱，
  那张券照样能领（只有"这单已经不是他了"才领不到）。

> 提醒：`delivery = claim` 时**别把礼包当成"用户已经有了"**去做客服判断 —— 他没点，
> 权益就真的还没到账。客服要看的是"有没有待领取的券"，不是订阅有没有变。

#### 两种送达都会发一封通知邮件（默认开，可关）

| | 邮件写什么 | 为什么必须发 |
|---|---|---|
| **待领取** | 送什么 · **几号之前有效** · 「去领取」按钮 | 券不发信 = 没人知道有券，等于白送 |
| **自动到账** | 加了多少 · **新的到期日是哪天** | 悄悄改账用户感知不到，只有"收据"能让他记住 |

- 礼包表单里「通知邮件」可以关（有些场景就是不想打扰）。**关掉 = 用户不会有任何感知。**
- 发信有**每日配额**（后台「设置 → 每日发信配额」，缺省 5000）。配额用尽时通知
  会顺延到次日 —— **券和权益照常发放**，只是晚点告诉他。留出的 10% 是给验证码的。
- 每封都带一键退订（只退营销类；验证码和订单结果不受影响）。
- ⚠️ 别把这里当群发工具：Cloudflare 的发信服务只允许交易类邮件。发促销广告会打掉
  域名信誉，**连带验证码登录一起挂**。

### 0.4 送达方式决定了它出现在哪（站内 / 站外）

| 送达方式 | 出现在哪 | 为什么 |
|---|---|---|
| **无码** | 站内（定价页 / App 套餐列表），或系统直发 | 用户不需要输凭证，只能靠我们主动给 |
| **有码**（共享码 / 一人一码） | **站外**：群、博主、实体卡、私信 | 渠道专属一旦人人可见，渠道方第一个不满意，渠道归因也一起失真 |

具体怎么配出来：

| 想投在哪 | 优惠券怎么配 | 礼包怎么配 |
|---|---|---|
| 站内 | 「怎么生效 → 生效方式」选**自动生效**（角标必填） | 不用配；靠人群触发（首单 / 快到期）+ 后台发放 |
| 站外 | 生效方式选**凭码使用**，再选共享码还是一人一码 | 发码方式选共享码或一人一码 |

所以凭码的东西「定价页展示」是**强制关闭**的，不是你忘了开 —— 你甚至看不到那个开关。

### 0.5 两条永远不会变的规则

1. 每人每活动**只能享 1 次**（同一个人反复用同一个优惠，违背营销语义，也让"核销次数 = 触达人数"这条口径失效）。
2. 一单**最多用一个活动**（同时命中多个时自动取更优，不叠加）。

## 2. 拉新与首单转化

<a id="s1"></a>
### S1 新客首单立减（全站可见）

- **工具**：优惠券
- **设置**
  1. 促销 → 优惠券 → 新建
  2. 名称：`新人首单立减 5 元`（只有后台可见）
  3. 怎么生效 → 生效方式：**自动生效（打开就看见，不用码）**
  4. 发给谁 → 人群：**新客（还没付过钱）**
  5. 力度 → 方式「减固定金额」，金额 `5`
  6. 展示 → 定价页展示：**开**；角标文案：`首单立减 ¥5`
  7. 保存 → 上线
- **用户看到**：定价页那张卡片显示 `限新用户 · 首单立减 ¥5`，价格直接是折后价；结账不用输码。
- **注意**：`限新用户` 是系统自动加的，不用自己写；角标不许空（自动券没有码、没有入口，定价页是它唯一的曝光位）。

<a id="s2"></a>
### S2 限时 3 天大促

- **工具**：优惠券
- **设置**：同 S1，另外在「有效期」填开始时间 / 结束时间。
- **用户看到**：时间窗之外，定价页不再出现角标、结账也不能用 —— 不需要你手动下线。
- **注意**：已经发出去的码不受影响，但码里如果单独设了过期时间，以更早的为准。

<a id="s3"></a>
### S3 前 100 单限量

- **工具**：优惠券（自动生效）
- **设置**：展示 → **总名额 = 100**。
- **用户看到**：第 101 单起自动恢复原价，角标消失。
- **注意**
  - 总名额只对**自动生效**的券有意义；凭码券的名额在码上。
  - 留空 = 不限；要限制就填 ≥ 1 的整数（填 0 会被拒 —— "0 单"不是不限，是没有意义）。
  - 名额在**付款到账后**才扣，所以"前 100 单"实际是"前 100 个付款的人"，报价阶段不占名额。

<a id="s4"></a>
### S4 只对刚注册 7 天内的人

- **工具**：优惠券
- **设置**：发给谁 → **注册 N 天内才能用 = 7**。
- **用户看到**：注册超过 7 天的人看不到角标，输码也会被拒（理由会告诉他原因）。
- **注意**：可以配合"人群=所有人"用 —— 这样"注册时间"成为唯一门槛，适合拉新期。

<a id="s5"></a>
### S5 只对某个套餐做活动

- **工具**：优惠券
- **设置**：适用范围 → 勾选套餐类型（周期 / 流量 / 加购），或填**指定套餐 ID**（逗号分隔）。
- **用户看到**：只有命中的套餐卡片带角标，其余套餐原价。

<a id="s31"></a>
### S31 注册即送 7 天免费试用

- **工具**：**免费试用套餐**（这是"套餐"，不是"活动"——区别见 [§0.2.1](#021-免费试用不是活动是一份套餐)）
- **设置**
  1. 套餐 → 新建：类型 = **周期**，周期（天）= `7`（**这就是试用时长**），每月额度 = `10`
  2. 设备数 = 与你要卖的正式套餐**保持一致**（1 / 2 / 3）
  3. 勾「**设为免费试用套餐**」—— 价格与可见性会被服务端锁定为 `0 元 / 隐藏`，填了也不生效
  4. 发布
- **用户看到**（文案全部由 CRM 给，你与 App 都不用拼）
  - 注册页：`注册即送 7 天免费试用（10GB）` —— 官网 / App 调 `GET /trial` 拿这句
  - 注册成功：订阅卡片 `免费试用 · 还剩 7 天` + 小标签「试用中」，**立刻能连**
  - 到期或流量用完：`试用已于 11-06 结束 · 升级后可继续使用` + 小标签「试用已结束」
- **注意**
  - **全库只能有一个**试用套餐。想换掉它：先把旧的那条取消勾选，再给新的勾上（否则保存会提示"已经有免费试用套餐"）。
  - 它**不会出现在定价页**，也没法被直接购买 —— 列表里没有它，接口下单一律拒绝。
  - 每人只开一次：试用到期后再用同一邮箱登录不会重新送；已开过试用的客户不会被再送一次。
  - **转正是自然发生的**：试用期间打开定价页，所有公开套餐都显示为"升级"，按**全价**付款 —— 试用实付 0，不产生残值，也就不折钱。
  - 试用期**不要**同时开「到期前送天数」（[S13](#s13)），那等于免费续期。
  - ⚠️ 设备数与正式套餐不一致的话，用户转正时平台会删旧建新并**换激活码**，他要重新登录客户端。
- **想再多送一点？** 用礼包叠加（[S12](#s12) 首单后送）；**对单个客户**的临时补偿走客户页「调整权益」（[S21](#s21)）。两者都只加天数或流量，不改"试用"这个性质。

<a id="s12"></a>
### S12 首单后额外送 7 天

- **工具**：礼包
- **设置**
  1. 促销 → 礼包 → 新建
  2. 送什么 → 送天数 = `7`
  3. 发给谁 → 人群 = **新客**
  4. （可选）没订阅的人怎么办 → 选一个隐藏的体验套餐做兜底。**配了免费试用（S31）就用不到** —— 那时新客注册即有一行订阅
  5. 上线
- **用户看到**：**首单付款成功后**自动到账，无需操作。
- **注意**
  - 时机是"首单开通之后"而不是注册那一刻 —— 新注册没有订阅，天数无处可放。
  - **送达方式选「待领取」**（[§0.3.1](#031-礼包的两种到账方式自动到账-vs-待领取)）：
    否则这 7 天是静默加上的，用户根本不知道自己被多送了 7 天，营销就白做了。
  - 目前这一项**不会出现在定价页**（赠品位规划中），属于"售后惊喜"而不是"购买激励"。

<a id="s13"></a>
### S13 到期前送 7 天（无条件）

- **工具**：礼包
- **设置**：人群 = **快到期**；`N 天内到期 = 7`；送什么 → 送天数 = `7`。
- **用户看到**：符合条件的订阅自动延长 7 天，每天跑一次扫描。
- **注意**
  - 每人每活动只能发 1 次，不会反复加。
  - ⚠️ 如果用户正处在**免费试用**（[S31](#s31)），这条会给他**续期试用**而不是逼他转化 —— 做试用期转化时不要同时开它。
  - 默认是**静默发放**（`auto`）：系统不通知，用户要靠自己看有效期才知道。
    **想让用户知道就选「待领取」**（[§0.3.1](#031-礼包的两种到账方式自动到账-vs-待领取)）——
    App 的「我的礼包」会多一张卡，写着「+7 天 · 5 天后作废」。
  - 主动推送 / 邮件通知还没做（见 [§10](#10-暂不支持规划中)）。

## 7. 服务补偿（不走营销活动）

> **补偿 != 营销。** 故障补偿、投诉安抚是**对一个人**的兑付，不该产生 0 元订单、
> 不该进营销统计、也不该绑定人群/名额。所以它走**特殊通道**：
> 客户页 -> 「调整权益」-> 填天数/流量 + **必填原因**。见 `docs/domain.md` 4.5。

<a id="s21"></a>
### S21 故障补偿送 3 天

- **工具**：客户页 -> 「调整权益」（不是礼包）
- **设置**：加天数 = `3`，原因写清楚（例：`11-03 线路故障补偿`），提交。
- **用户看到**：有效期在原到期日上 +3 天，App 刷新即可看到。
- **留痕**：`adjustments` 一行（before/Δ/after + 原因 + 操作人）+ 台账 `adjust`
  + 审计 `subscription_adjusted`。**不生成订单**，财务收入里看不到它。

<a id="s22"></a>
### S22 投诉安抚送流量

- **工具**：客户页 -> 「调整权益」
- **设置**：加流量 GB = `50`，原因必填。
- **注意**：流量加在**平台真实剩余**上（写前强制回源，不用 15 分钟缓存），
  同时进**额外流量池**（不覆盖本月套餐额度，也不随月度重置清零）。
  不限量的订阅加不了 GB，会直接报「不适用」。

<a id="s23"></a>
### S23 两项一起送（天数 + 流量）

- **工具**：客户页 -> 「调整权益」，一次填两个字段。
- **注意**：两个维度**各改各的**：天数只延长到期日，GB 只加流量（period 进额外流量池，
  traffic 抬高整包）。订阅是**无限期**就不加天数、**不限量**就不加 GB —— 那一项自动忽略，
  另一项照常生效。两项都用不上时请求会被拒绝（不会有「什么都没发生但显示成功」）。

<a id="s24"></a>
### S24 只给指定名单发

- **工具**：礼包 / 优惠券
- **设置**：人群 = **指定客户**，然后在「发给谁」里维护名单。
- **注意**：定向活动**永远不会公开**（定价页不出现，即使开了展示）。

## 9. 活动管理

<a id="s26"></a>
### S26 上线 / 下线

- **状态**：草稿 →（上线）→ 进行中 →（结束）→ 已结束。
- **注意**：**草稿对用户完全不生效**；上线是单独一步，防止误发。

<a id="s27"></a>
### S27 改一个已经发过码的活动

码一旦发出去，规则就在外面流通了（500 个渠道码可能只用了 3 个，但另外 497 个在用户手里）。所以：

| 发过码之后 | |
|---|---|
| **不能改** | 生效方式、力度 / 礼包内容、适用范围、体验套餐 |
| **可以改** | 名称、角标文案、定价页展示、人群、冷却时间、结束时间、追加发码、总名额调大 |

把码全部作废后自动解锁。服务端也会拦（返回"活动已锁定"），不是只靠界面。

<a id="s28"></a>
### S28 删掉建错的活动

- **条件**：**草稿** + 没有码 + 没有任何核销记录，三者同时满足才能删。
- **否则**：请「结束」它，保留历史数据。

<a id="s29"></a>
### S29 上线前怎么验证

- **先说清楚**：促销**没有**“预览/试算”功能（套餐那边有，促销没有）。后台只能预览名字和数字，看不到真实结算结果。
- **可执行的做法**
  1. 先存**草稿**（草稿对用户完全不生效），把名称/力度/范围/角标再核一遍
  2. 把人群改成**指定客户**，名单里只放自己的测试账号
  3. 上线 → 用该测试账号在 App / 官网走一遍：定价页有没有角标、结账金额对不对
  4. 验证完把人群改回真正的目标人群（没发过码就能改）
- **注意**：一旦发过码，“人群”仍然能改，但**力度/范围/生效方式**就锁住了 —— 所以先验证再发码。

<a id="s30"></a>
### S30 同一单能用几个优惠

- **只能用一个**：同时命中多个活动时自动取更优的，不叠加。
- **券 + 礼包可以同时生效**：一个改价格、一个改权益，本来就是两本账。

## 11. 一次记住的通用规则

1. **每人每活动 1 次**，同一个人不能反复薅。
2. **一单一个活动**，取更优不叠加。
3. **角标 = 系统人群前缀 · 你的文案**。前缀（限新用户 / 限续费用户 / 限 N 天内到期 / 限订阅已结束）自动加，改不掉。
4. **自动生效的券必须有角标**；凭码券**永远不进定价页**。
5. **名额位置**：自动券在活动上（总名额），凭码券在码上（共享码 = 1 码 N 人，一人一码 = 每码 1 次）。
6. **礼包的"适用范围"按客户当前订阅的套餐判定**，不是按他要买的套餐 —— 与优惠券不同，配之前想清楚。
7. **礼包必须有地方放权益**：客户有订阅，或者你配了体验套餐；否则发放会被跳过（并留痕），不会凭空产生天数。
8. **每次礼包发放 = 一张 0 元已付订单**，用来对账。
9. **免费试用是"套餐"，不是"活动"**：全库只能一个，注册即自动开通，不进定价页也不能买（[S31](#s31)）。礼包负责"再多送"，它负责"从零开始"。
